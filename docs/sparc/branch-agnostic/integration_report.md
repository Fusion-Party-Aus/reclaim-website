## Findings and disposition

### Closed — Real branch builds now run parity and leakage verification

The verifier is wired to the real build path by `verify:branches`, and CI invokes that command. Each manifest entry gets an isolated build output; verification runs against that branch's collected build output. CI no longer depends on a manually maintained two-branch build matrix. The latest supplied run passed for both registered branches.

**Residual scope:** Leakage verification scans selected textual output files and known token classes. It does not prove absence of every possible foreign value in every generated file type or binary asset.

### Closed — Studio app-ID override is validated with other binding overrides

The CLI now passes the app-ID override into `resolveBranch`; the resolver applies it before collision validation. The resolved app ID is then used by Sanity CLI config. The prior post-validation override bypass no longer exists in this path.

### Closed — Theme imports and actual CSS declarations are manifest-checked

The theme generator derives the import index from registered manifest slugs and validates both token-contract shape and mapped CSS property declarations against each branch's theme file. Pre-build generation makes the index current for normal builds and fails when a manifest branch lacks a theme file or required declaration.

### Closed — Generic branch commands use manifest default; CI checks are non-mutating

The generic branch wrapper defaults to `branchManifest.defaultBranch`. CI invokes `npm run lint` and `npm run format:check`, not auto-fix commands. CI delegates branch build coverage to the manifest-iterating `verify:branches` command.

### Closed — Generic dataset provisioning command is available

`npm run provision:branch -- --acl public|private` resolves a registered branch from the manifest, creates its configured dataset if absent, and seeds missing singleton documents with create-if-absent semantics. The QLD command delegates to this generic implementation. ACL and write credentials are required before remote mutation.

### Residual — Sanity/Cloudflare resource creation and manifest registration remain operator steps

The generic command does not create Sanity projects or hosted Studio apps, generate a complete new branch manifest entry, create Cloudflare Workers/KV namespaces, configure DNS/domains, or configure analytics/CORS/integration credentials. Those external resources and IDs must be established and entered before the new branch can build and deploy.

### QLD proof branch completed; future provider setup remains configuration/operations

Per maintainer direction, Queensland is the first non-Victoria proof branch; NSW is not being provisioned because no NSW project/resources exist. QLD's manifest-driven builds verify the shared framework without a cloned application. A future branch still needs a manifest data entry, theme CSS, asset/content choices, Wrangler/KV identifiers, and external Sanity/Cloudflare resources. That remains configuration/provider setup rather than copied application code, but it is not a one-click setup from a Sanity project alone.

### Residual — Legacy runtime shape remains the application-facing contract

`config/deployment.mjs` still adapts manifest `runtime` values into the legacy shape used by components. Resolver-derived presentation is based on that runtime for the current entries. This is coherent for the current manifest, but leaves the compatibility adapter and embedded runtime schema as required integration points for future branches; the framework does not yet make all consumers read the resolved descriptor directly.

## Overall assessment

The implementation closes the #13 software path using Queensland as the first non-Victoria proof: branch-specific resolution/presentation, themes/assets/analytics policy, adopted-only machine-readable policy output, generic dataset/starter provisioning, manifest-selected one-command deploy, manifest-driven CI and built-output verification. Final Vitest, TypeScript and both-branch verification pass. External provider resources remain manual; future branches require manifest/theme/resource configuration, but no application code is cloned. The package and lockfile versions are both `0.1.0`.
