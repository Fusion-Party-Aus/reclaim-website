## Medium

### Provisioning can leave created remote resources when a later step fails

- **References:** `config/branch/provision.mjs:264-287` (Wrangler-path validation and preflight candidate validation); `config/branch/provision.mjs:318-327` (remote project/dataset/Studio ID resolution); `config/branch/provision.mjs:329-337` (final entry validation and Studio deployment); `config/branch/provision.mjs:339-355` (document seeding and manifest write).
- **Finding:** Caller-supplied bindings are checked before adapter calls, and the completed entry is checked before Studio deployment, seeding and manifest write. However, when a project or Studio app ID is generated by an adapter, final entry validation happens only after resource resolution at lines 318-327. Failures later in the sequence can also leave successful remote changes without a manifest update. The code records some completed side effects on errors, but this is not transactional rollback.
- **Impact:** A failed or unexpectedly colliding generated binding can leave orphaned resources; deployment/seeding/writer failures can leave remote configuration or content partially applied.
- **Suggested follow-up:** Treat partial provisioning as an explicit recovery state: return/report completed operations consistently, and provide cleanup or reconciliation procedures. Where generated bindings can be validated before mutation, perform that validation first.

## Closed / remediated findings

- **Provisioning binding isolation before side effects — remediated for caller-supplied values.** `config/branch/provision.mjs:280-287` constructs and resolves a candidate entry before adapter operations. Its final resolved entry is checked again at lines 329-335. `config/branch/provision.test.js:213-221` covers rejection of a cross-branch project/dataset binding before adapter calls. The residual generated-resource/partial-failure limitation is recorded above.
- **Wrangler path escape — remediated.** `config/branch/deploy.mjs:42-61` rejects absolute paths, traversal segments and non-Wrangler TOML names and enforces repository containment; lines 104-126 check existence and canonical real-path containment, including symlink escapes. `config/branch/provision.mjs:264-279` applies corresponding lexical restrictions before persisting a supplied path. Coverage is present in `config/branch/deploy.test.js:151-162`.
- **Unsafe or cross-origin asset destinations — remediated in asset resolution.** `config/branch/assets.mjs:31-48` rejects control/backslash characters, protocol-relative and encoded traversal forms, dot segments, non-HTTPS or off-origin absolute URLs, and explicit foreign-branch asset markers. `config/branch/assets.test.js:93-114` covers foreign, traversal and external destinations. Root-relative shared assets are intentionally supported (test lines 105-109).
- **Unsafe navigation and CTA hrefs — remediated.** `config/branch/presentation.mjs:7-22` restricts destinations to safe root-relative or credential-free HTTPS URLs and rejects executable schemes, protocol-relative URLs, control characters and traversal forms. Validation is applied to navigation and CTAs at lines 35-64 and 125-156. Tests cover unsafe schemes and accepted destinations at `config/branch/presentation.test.js:181-196`; `config/branch/resolver.mjs:339-349` also validates manifest/runtime presentation inputs.
- **Unrestricted site URL override — remediated.** `config/branch/resolver.mjs:47-54` validates canonical HTTP(S) origins; lines 101-106 validate configured allowed origins; lines 155-164 require an override to match the branch allowlist and normalize it to the origin. `config/branch/resolver.test.js:91-102` covers allowed and rejected overrides. `config/deployment.mjs:66-80` consumes the resolver's canonical origin.
- **Public-by-default dataset creation — remediated.** `config/branch/provision.mjs:253-262` requires an explicit valid `public` or `private` ACL mode before mutations, and lines 163-170 pass the selected mode to dataset creation. This makes the choice explicit but does not independently establish that a selected ACL is appropriate for a particular dataset.
